# x402 tips (optional, experimental)

TipMUSD has one main way to tip: a person opens a creator's link, connects a wallet and sends
`MUSD.transfer(creatorWallet, amount)` themselves. That never changes and never depends on anything below.

**x402 is a second, optional rail for software**: AI agents, bots, scripts and backends that want to tip a creator
by making an HTTP request. It is off unless the server sets `X402_ENABLED=1`, and it only runs on **Mezo Testnet**.

## What x402 is

[x402](https://www.x402.org) revives HTTP status `402 Payment Required` as a payment handshake:

1. The client requests a resource.
2. The server answers `402` with a `PAYMENT-REQUIRED` header: what to pay, to whom, on which network.
3. The client signs a payment authorization and retries with a `PAYMENT-SIGNATURE` header.
4. The server has a **facilitator** verify and settle the payment on chain, then returns the resource plus a
   `PAYMENT-RESPONSE` header describing the settlement (tx hash, payer, network).

For TipMUSD the "resource" is the tip itself: the response body is the tip receipt.

## Why it's a separate rail

- An ordinary tip is the simplest possible payment: a plain ERC-20 transfer the supporter signs and pays gas for.
  No third party touches it.
- x402 adds a third party (the facilitator) that submits the transaction and pays the gas. That is useful for
  software that holds MUSD but no BTC for gas and can't click through a wallet, but it adds trust and availability
  risk. So it lives in its own route (`/api/x402/*`) and its own code (`lib/server/x402/*`), and the tip page never
  calls it.

## Flow

```
agent / script                       TipMUSD server                    facilitator              Mezo Testnet
     |  GET /api/x402/tip/alice?amount=2   |                                |                         |
     |------------------------------------>|  validate amount, load @alice  |                         |
     |                                     |  payTo = alice's wallet (DB)   |                         |
     |  402  PAYMENT-REQUIRED (base64)     |                                |                         |
     |<------------------------------------|                                |                         |
     |  sign Permit2 PermitWitnessTransferFrom (+ EIP-2612 permit, 1st time) |                         |
     |  GET … + PAYMENT-SIGNATURE          |                                |                         |
     |------------------------------------>|  POST /verify ---------------->|                         |
     |                                     |  POST /settle ---------------->|  x402 proxy → Permit2 → |
     |                                     |                                |  MUSD.transferFrom      |
     |                                     |                                |  (payer → alice) ------>|
     |                                     |  { success, transaction, payer }                         |
     |                                     |<-------------------------------|                         |
     |                                     |  read receipt: MUSD Transfer payer → alice, value == 2   |
     |                                     |--------------------------------------------------------->|
     |                                     |  insert tips row (source='x402', confirmed)              |
     |  200 X402TipReceipt + PAYMENT-RESPONSE                               |                         |
     |<------------------------------------|                                |                         |
```

Order of checks on the server (`lib/server/x402/handler.ts`):

1. `X402_ENABLED` must be `1`, otherwise `404 { error.code: "x402_disabled" }`.
2. Rate limit per client IP (`X402_RATE_LIMIT_PER_MINUTE`, default 20).
3. Validate `amount` (0.01–10000 MUSD, at most 6 decimals), `name` (≤ 40 chars), `message` (≤ 280 chars). Text is
   cleaned (control and bidi characters removed) and always shown as plain text.
4. Load the creator from the database (active profiles only; retired usernames resolve to their owner).
   **`payTo` is the creator's wallet from the database. Nothing in the request can change it.**
5. No payment header → `402`. With a payment → facilitator `/verify`, then `/settle`.
6. **We don't take the facilitator's word for it.** We read the settlement transaction from Mezo ourselves and
   require a MUSD `Transfer` log from the payer to the creator's wallet with exactly the requested amount.
7. Save the tip (`source = 'x402'`). The transaction hash is unique: if the indexer already recorded this transfer,
   or the same request is retried, we link to that row instead of creating a second one.
8. If the receipt isn't visible yet or doesn't have enough confirmations (`CONFIRMATIONS`, default 2), the tip is
   saved as `pending_confirmation` and finished by the background check (`verifyX402Tip` / `sweepPendingX402Tips`
   in `lib/server/x402/verify.ts`).

## Facilitator, Permit2 and EIP-2612

- **Facilitator**: `https://facilitator.vativ.io` by default (listed in the
  [Mezo x402 docs](https://mezo.org/docs/developers/getting-started/musd-payments-x402/); community run, no API key).
  Its `/supported` endpoint advertises x402 v2, scheme `exact`, networks `eip155:31611` (testnet) and
  `eip155:31612`, and the `eip2612GasSponsoring` extension.
- **Network id** is CAIP-2: `eip155:31611`.
- **Asset**: MUSD `0x118917a40FAF1CD7a13dB0Ef56C86De7973Ac503` (18 decimals). The price is sent as an exact
  base-unit amount of this token, not a "$" price, so there's no USD conversion.
- **MUSD has no EIP-3009** (`transferWithAuthorization`), so the `exact` scheme uses **Permit2**
  (`0x000000000022D473030F116dDEE9F6B43aC78BA3`). The payer signs a `PermitWitnessTransferFrom` whose spender is the
  x402 proxy `0x402085c248EeA27D92E8b30b2C58ed07f9E20001`; the facilitator calls the proxy, which pulls the MUSD
  from the payer straight to the creator. Funds never pass through TipMUSD or the facilitator.
- **First payment from a new wallet**: Permit2 needs an ERC-20 allowance. MUSD supports **EIP-2612** permits
  (domain `"Mezo USD"`, version `"1"`), so our 402 declares the `eip2612GasSponsoring` extension. A client that can
  read the chain (`@x402/evm` `ExactEvmScheme` with `rpcUrl`, or a signer with `readContract`) then also signs a
  permit for Permit2, and the facilitator submits it in the same settlement. Without it the server answers
  `412 permit2_allowance_required`.

## Who pays gas

The facilitator. The payer only needs MUSD and signs messages; no BTC is needed. TipMUSD pays nothing and holds no
keys.

## Environment

| Variable | Default | Meaning |
|---|---|---|
| `X402_ENABLED` | off | `1` turns the rail on. Off → `/api/x402/tip/*` answers 404 `x402_disabled`. |
| `X402_FACILITATOR_URL` | `https://facilitator.vativ.io` | Facilitator base URL. |
| `X402_FACILITATOR_TIMEOUT_MS` | `60000` | Per facilitator request. A settle timeout means the outcome is unknown. |
| `X402_RATE_LIMIT_PER_MINUTE` | `20` | Per client IP, counts unpaid probes too. |
| `MEZO_RPC_URL` | `NEXT_PUBLIC_MEZO_RPC_URL` or `https://rpc.test.mezo.org` | RPC used to check settlement transactions. |
| `CONFIRMATIONS` | `2` | Shared with app tips. |
| `NEXT_PUBLIC_APP_URL` | `http://localhost:3000` | Used for the endpoint template in `/api/x402/info`. |

Script only: `X402_PAYER_PRIVATE_KEY` (payer key, never printed), `X402_PAYER_NAME` (optional supporter name).

  "enabled": true,
  "network": "eip155:31611",

  "asset": "0x118917a40FAF1CD7a13dB0Ef56C86De7973Ac503",

```

### `GET /api/x402/tip/{username}?amount=2[&name=…][&message=…][&anonymous=1]`

Without payment you get the 402 (the machine-readable requirements are in the `PAYMENT-REQUIRED` header, base64
JSON; the body is a readable summary):

   "asset": "0x118917a40FAF1CD7a13dB0Ef56C86De7973Ac503", "payTo": "0x…", "maxTimeoutSeconds": 300,
   "extra": { "name": "Mezo USD", "version": "1", "assetTransferMethod": "permit2" } }]
```

After payment: `200` with `X402TipReceipt` (`lib/api-types.ts`) and a `PAYMENT-RESPONSE` header:

```json
{
  "tip": { "id": "…", "status": "confirmed", "source": "x402", "amountRaw": "2000000000000000000",
           "txHash": "0x…", "explorerUrl": "https://explorer.test.mezo.org/tx/0x…", "message": "gm", "…": "…" },
  "settlement": { "transaction": "0x…", "network": "eip155:31611", "payer": "0x…" }
}
```

`tip.status` can be `pending_confirmation` if the chain hadn't confirmed it yet; poll `GET /api/tips/{id}`.

Errors (all `{ error: { code, message, details? } }`):

| Status | Code | Meaning |
|---|---|---|
| 400 | `invalid_amount`, `amount_out_of_range`, `invalid_text` | Fix the request. Nothing was charged. |
| 404 | `not_found`, `x402_disabled` | Unknown/suspended creator, or rail off. |
| 402 | `x402_settlement_failed` | Facilitator refused to settle (e.g. it ran out of testnet BTC for gas). Nothing recorded. |
| 412 | (x402 body `permit2_allowance_required`) | Client didn't attach the EIP-2612 permit; give it an RPC URL. |
| 429 | `rate_limited` | Slow down. |
| 502 | `x402_facilitator_error`, `x402_settlement_unverified` | Facilitator error, or the settlement tx didn't pay this creator exactly. |
| 503 | `x402_facilitator_unavailable` | Facilitator unreachable at startup. |
| 504 | `x402_settlement_unknown` | Settle timed out: the payment may still land. Check the explorer before retrying. |

## Script

```
X402_PAYER_PRIVATE_KEY=0x… npx tsx scripts/x402-tip.ts http://localhost:3000 alice 1.5 "thanks for the thread"
```

It reads the creator's public wallet first and refuses to pay anything other than exactly that amount of MUSD on
Mezo Testnet to that wallet, then prints the receipt and the explorer link. Use a throwaway testnet key with a bit
of MUSD (faucet: <https://faucet.test.mezo.org>); it needs no BTC.

## Agent example

```ts
import { createPublicClient, http, parseUnits } from "viem";
import { privateKeyToAccount } from "viem/accounts";
import { wrapFetchWithPaymentFromConfig } from "@x402/fetch";
import { ExactEvmScheme } from "@x402/evm/exact/client";
import { toClientEvmSigner } from "@x402/evm";

const rpcUrl = "https://rpc.test.mezo.org";
const account = privateKeyToAccount(process.env.AGENT_KEY as `0x${string}`);
const publicClient = createPublicClient({ transport: http(rpcUrl) });
const MUSD = "0x118917a40FAF1CD7a13dB0Ef56C86De7973Ac503";

export async function tipCreator(username: string, amount: string, message: string) {
  const pay = wrapFetchWithPaymentFromConfig(fetch, {
    schemes: [{ network: "eip155:31611", client: new ExactEvmScheme(toClientEvmSigner(account, publicClient), { rpcUrl }) }],
    // Hard cap: never more than this tip.
    spendControls: { allowedAssets: [{ network: "eip155:31611", asset: MUSD, maxAmountPerPayment: parseUnits(amount, 18).toString() }] },
  });
  const url = `https://tipmusd.app/api/x402/tip/${username}?amount=${amount}&message=${encodeURIComponent(message)}`;
  const res = await pay(url);
  if (!res.ok) throw new Error(`tip failed: ${res.status} ${await res.text()}`);
  return res.json(); // X402TipReceipt
}
```

Note: `@x402/fetch` caps payments at `$1` by default; set `spendControls` as above for larger tips.

## Implementation notes

- We use `@x402/core`'s `x402HTTPResourceServer` directly rather than `@x402/next`'s `withX402`, because `withX402`
  settles *after* the route handler returns, so the handler can't see the settlement tx hash it needs to verify and
  record the tip. `payTo` and `price` are per-request dynamic values (`DynamicPayTo` / `DynamicPrice`) read from the
  validated request.
- x402 tips have no calldata `ref` (the facilitator sends the tx), so the app-tip verifier can't verify them. Their
  verification lives in `lib/server/x402/verify.ts`; the background sweep calls `sweepPendingX402Tips` and anything
  that re-verifies a tip by id dispatches `source = 'x402'` to `verifyX402Tip`.
- Packages are pinned: `@x402/core|evm|fetch|extensions|next` `2.30.0` (≥ 2.10 is needed for Mezo Testnet).

## Limits and risks

- **Community facilitator.** Run by a third party, not by Mezo or TipMUSD. It can be down, slow, or change.
  The rail fails closed: if it is unreachable, no payment is requested or recorded.
- **Thin facilitator gas.** Its signers hold small amounts of testnet BTC. When they run dry, settlement fails with
  `x402_settlement_failed`; nothing is charged.
- **Settle timeouts are ambiguous.** A timed-out settle may still land. If it does, the indexer records the transfer
  as an ordinary tip (without the message).
- **First-time Permit2 permit.** The first payment from a wallet signs an EIP-2612 permit giving Permit2 an
  allowance (usually unlimited). That allowance stays after the tip; revoke it in a wallet tool if you care.
- **Testnet only.** MUSD and BTC on Mezo Testnet have no value. Mainnet would need its own review.
- **Messages are unverified identity.** `name` is whatever the agent sends; the payer address is the only proof.

## Ideas for later

- **Paid creator content**: put a post, file or stream behind `402` priced by the creator, paid straight to their
  wallet the same way.
- **Pay-per-request APIs**: creators selling small API calls or AI outputs per request.
- **Agent tipping rules**: an agent that tips creators whose content it used, within a budget.
- **Our own facilitator** (or several) for redundancy and to remove the third-party dependency.
